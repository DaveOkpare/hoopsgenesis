# `/api/v1` endpoints

Reference: `v1/audit-log.ts` (logic), `routes/api/v1/academies/$academyId/audit-log.ts` (route), `v1/audit-log.test.ts` (tests).

## Where files go

- Logic: `src/server/api/v1/<resource>.ts`. Export one `apiHandler(...)` per method and path. Import helpers from the files below, never from an index.
- Route: one thin file per path under `src/routes/api/v1/`. A `$name` folder or file is a path param. For example, `/api/v1/academies/:academyId/attendance/:id/void` goes in `routes/api/v1/academies/$academyId/attendance/$id/void.ts` with `createFileRoute("/api/v1/academies/$academyId/attendance/$id/void")`. `routeTree.gen.ts` is regenerated by `vite dev` or `vite build` and is gitignored.

```ts
// routes/api/v1/academies/$academyId/fees/$id/void.ts
import { createFileRoute } from "@tanstack/react-router";
import { voidFee } from "@/server/api/v1/fees";
export const Route = createFileRoute("/api/v1/academies/$academyId/fees/$id/void")({
  server: { handlers: { POST: voidFee } },
});
```

## Skeleton

```ts
export const voidFee = apiHandler(async (ctx) => {
  const { session, member, academy } = await requireAcademyAccess(ctx, { fee: ["void"] }); // 401, 404, 403
  const { id } = parseParams(z.object({ id: idSchema }), ctx.params);                       // 400
  const input = parseBody(z.object({ reason: z.string().trim().min(1) }), await readJsonBody(ctx.request));
  const updated = await db.$transaction(async (tx) => {
    const before = await tx.fee.findFirst({ where: { id, academyId: academy.id } }); // always filter on academy.id
    if (!before) throw new NotFoundError("Fee not found");
    if (before.voidedAt) throw new ConflictError("Fee already voided", { code: "already_voided" });
    const after = await tx.fee.update({ where: { id }, data: { voidedAt: new Date(), voidedById: session.user.id, voidReason: input.reason } });
    await writeAuditLog(tx, { request: ctx.request, session, academyId: academy.id, action: "fee.void",
      entityType: "fee", entityId: id, before, after, reason: input.reason });
    return after;
  });
  return json({ data: serializeFee(updated) }); // serializeFee uses ./serialize.ts
});
```

## Helpers

| File | Use |
| --- | --- |
| `handler.ts` | `apiHandler`, `json`, `created`, `noContent`. Thrown `ApiError`, `ZodError` and Prisma P2002/P2025 errors become `{ error: { code, message, details? } }`. `apiHandler` also refuses any POST/PUT/PATCH/DELETE whose body is not JSON or empty (400 `unsupported_content_type`, before access checks), so body-less actions are safe from cross-site form posts too; only the payment webhook passes `{ anyContentType: true }` |
| `route-guard.ts` | Mounted once on the `/api/v1` layout (`routes/api/v1/route.ts`): a wrong method is 405 `method_not_allowed` with `Allow`, an unknown path 404 `not_found`, both JSON. New route files need nothing extra |
| `errors.ts` | `ValidationError` 400, `UnauthorizedError` 401, `ForbiddenError` 403, `NotFoundError` 404, `ConflictError` 409, `GoneError` 410 (it existed but can no longer be used), `RuleViolationError` 422. Pass `{ code: "outside_window", details }` for specific codes |
| `validation.ts` | `readJsonBody`, `parseBody`, `parseQuery` (both reject unknown keys; use `z.strictObject` for nested objects), `parseParams`; `idSchema`, `isoDateSchema`, `timeOfDaySchema`, `timestampSchema`, `moneyAmountSchema`, `currencySchema` |

## Secrets: invitation ids and invitation codes

- An invitation id (Better Auth `invitation.id`) and an invitation code (`invitation_code.code`) let whoever holds them join an academy. Only the platform owner and that academy's admins may receive them, and academy admins never receive one for an `admin` invitation or code. Coaches and students get none from any route: `packages/auth/src/index.ts` (plugin `invitation-privacy`) refuses `list-invitations` to non-admins and strips invitations from `get-full-organization`; `invitation-exposure.test.ts` checks every route.
- Never log them and never write them to `audit_log`: store `secretFingerprint(value)` (as `entity_id = "fp:<fingerprint>"` when the secret is the entity). `handler.ts` logs paths with invitation ids replaced by `:id`.
- Codes: `v1/invitation-codes.ts` (manage, preview, redeem) and `v1/invitation-code-format.ts` (generation, normalization, `<BETTER_AUTH_URL>/join/<code>` and `hoops-genesis://join?code=<code>`). Code values travel in POST bodies, never in a URL path of the API.
- An endpoint that adds someone to an academy outside Better Auth applies the same rules as Better Auth's hooks through `@hoops-genesis/auth/membership-rules` (`isValidAcademyRoleList`, `isPlatformAdminUser`, `isOnAnotherTeam`, `teamMembershipKey`), creates `member` and `teamMember` rows with `newId` (Better Auth's id generator, `v1/admin-academies.ts`), sets `teamMember.membershipKey` and bumps `team.memberCount`, and audits `team.member_add` like the roster hook does.

## Roles

- **Platform owner**: `user.role = 'admin'` (admin plugin). Never an academy member. Acts only through `/api/v1/admin/*` (guarded by `requirePlatformAdmin`) and Better Auth's `admin.*` API. `v1/admin-academies.ts` creates and deletes academies and appoints and removes academy admins by writing the rows itself.
- **Academy roles** (`member.role`, comma-separated): `admin`, `coach`, `student`, defined in `packages/auth/src/permissions.ts`. Better Auth's built-in `owner` and `member` roles are not used; hooks in `packages/auth/src/index.ts` refuse them.
- Writes check `member.isAdmin` (never "admin or owner"). Reads that cover the whole academy check `member.seesWholeAcademy` (true for admins). Keep the two apart: a read-only platform-owner view can pass `toAcademyViewer(academyId, session.user.id)` as the member, which sees everything and passes no write or permission check.
- The platform owner reads any academy through GET routes under `/api/v1/admin/academies/$academyId/` (see "Platform owner views" below), never by becoming a member. For hands-on support they impersonate (Better Auth `admin.impersonateUser`); actions taken then are audited with `actor_id` = the account used and `impersonated_by` = the owner, and Better Auth's after hook (`packages/auth/src/index.ts`) writes `user.impersonate_start` / `user.impersonate_stop` rows.
- A platform admin is never an academy member: Better Auth hooks refuse an invitation to their email, accepting one, and `addMember`; `admin.setRole` / `admin.updateUser` refuse to make someone a platform admin while they still belong to an academy (remove the memberships first; nothing is deleted automatically).
- Only the platform owner appoints, demotes or removes academy admins. Academy admins invite and manage coaches and students only.
- Coaches change rosters only through Better Auth (`organization.addTeamMember` / `removeTeamMember`), only on teams they are on, only for students. Each change writes an `audit_log` row from Better Auth's after hook (not in the same transaction as the roster change).

## Rules

- Check order: access first, then validation, so non-members get 404 and never 400.
- Scope every query with `academyId: academy.id`. Then narrow it: `scope === "all" ? {} : { studentId: { in: [...scope] } }`. For a single row outside the caller's scope, return 404.
- Take `recordedById`, `createdById`, `voidedById` and the actor from `session.user.id`, never from the body.
- Money goes out through `toMoneyString` and comes in through `moneyAmountSchema`, then `new Prisma.Decimal(input.amount)`. Never use `Number`.
- "Today" and `from`/`to` filters use `academy.timezone`: `localDateRangeToUtc` for timestamps, `plainDateRange` for date columns.
- Pagination: `orderBy` must end with `id`, and you fetch `take: limit + 1`. Time cursors assume millisecond timestamps, which Prisma writes. Raw SQL `now()` has microseconds, so do not use it for those columns.
- POSTs that create money or attendance rows use `withIdempotency(..., required: true)` and do all their writes on its `tx`. Read the body once with `readJsonBody`, then pass the same value to `parseBody` and to `withIdempotency`.

## Responses

- Every `...ById` field keeps its id and gains a sibling with the name: `voidedById` + `voidedBy: { id, name }` (null when the id is null). Records get them from Prisma includes (`records-shared.ts`); other rows use `people.ts`, loading everyone named on a page in one query. Never look people up per row.
- Attendance rows also carry `student: { id, name, image }` (`attendance-shared.ts` `serializeAttendanceRows`). Audit rows carry `actor` and `impersonatedById` + `impersonatedBy`.
- Bodies are `{ data }`, or `{ data, nextCursor }` for lists. Exception: `GET /academy-qr` returns `{ token, deepLink }` at the top level, as the API document shows.

## Platform owner views

A GET that the owner should also see is written once, as a factory over how the caller is found, then mounted twice:

```ts
// v1/fees.ts
export const listFeesFor = (resolve: AcademyAccessResolver): ApiHandler =>
  apiHandler(async (ctx) => {
    const { member, academy } = await resolve(ctx); // 401/404/403 come from resolve
    ...                                              // the same query and serializer
  });
export const listFees = listFeesFor(academyAccessWith({ fee: ["read"] }));

// v1/admin-academy-views.ts
export const adminListFees = listFeesFor(requireAcademyReadAccess);
```

`requireAcademyReadAccess` gives a `toAcademyViewer` member: `seesWholeAcademy` is true (every scope helper returns "all"), it has no roles, and `isAdmin` / `isCoach` / `isStudent` are false. So inside a shared handler, write whole-academy reads as `member.seesWholeAcademy` and every write or "may act" check as `member.isAdmin` / `isCoach` / a permission: the owner then reads everything and can do nothing. Export only GET handlers from `admin-academy-views.ts` and mount only `GET` on `routes/api/v1/admin/academies/$academyId/*` (a test checks every route file there). The owner's write actions inside an academy are limited to `admins/`, `admin-invitations/` and `invitation-codes/` (excluded from that test by name); add any other one to the test's exclusions on purpose.

## Tests

`pnpm --dir apps/web test` runs Vitest against the database in `apps/web/.env`, which must be local (`testing/setup.ts` checks this). Put `<resource>.test.ts` next to the logic file. Call the handler directly: `voidFee({ request: apiRequest(path, { user, method: "POST", body }), params: { academyId, id } })`. Build data with `testing/fixtures.ts`: `createTestAcademy`, `createTestUser` (a real session cookie), `addMember(academy, user, "coach,student")`, `createTeam`, `runId`, and `cleanup` in `afterAll`. Audit rows can never be deleted (they also keep their actor and impersonator), so use a new academy and unique entity ids in every run. Cover 401, 404 for non-members, 403, the scope limits, 409/422 rules and the error shape.
